## P1 — Should fix

### 2. CustomCursor leaks global listeners on every render + impure render side effects
- **Owner:** ui-component-builder (also raised by perf-a11y-auditor)
- **Files:** `src/app/_components/custom-cursor.tsx:16-21`
- **Why:** `document.body.addEventListener('mouseout'/'mouseover', ...)` runs in the render body with anonymous handlers and no cleanup. Because `onMouseMove`→`setPosition` re-renders on every pointer move, listeners accumulate unbounded, and since CustomCursor wraps the whole MainScreen/Three.js subtree, each setState re-renders the entire app.
- **Fix:** Move registration into `useEffect(() => {...; return () => removeEventListener(...)}, [])` with named handlers. Prefer a ref + requestAnimationFrame for position tracking to avoid re-rendering the subtree on every mousemove. (Optionally add the `"use client"` directive while in the file — see item 11.)

### 3. timeline() called as a side effect in render bodies (restarts every re-render)
- **Owner:** ui-component-builder
- **Files:** `src/app/_components/main-screen.tsx:6-14`, `src/app/_components/experience-section.tsx:4-9`, `src/app/_components/homepage/nav-list.tsx:9-22`
- **Why:** Animation timelines fire in the render body guarded only by `typeof document`. Combined with the CustomCursor re-render storm (item 2), every mouse move re-fires all timelines, restarting fade-ins continuously; also violates React's pure-render rule.
- **Fix:** Wrap each `timeline(...)` in `useEffect(() => {...}, [])` so it runs once after mount. Add `"use client"` to `main-screen.tsx` and `experience-section.tsx` (nav-list already has it). Note: this lands together with the item 1 motion migration, since both touch the same calls.

### 4. No `prefers-reduced-motion` support (perpetual particle rotation + fade-ins)
- **Owner:** perf-a11y-auditor
- **Files:** `src/app/_components/homepage/particle-display/particle-display.tsx:141`, plus all timeline call sites in `main-screen.tsx`, `nav-list.tsx`, `experience-section.tsx`, `particle-display.tsx:17`
- **Why:** Nothing honors reduced-motion. The WebGL field rotates every frame indefinitely (WCAG 2.2.2 Pause/Stop/Hide) and all components run fade-in animations. A vestibular-accessibility gap.
- **Fix:** Add a `usePrefersReducedMotion` hook. When reduced motion is set: skip the `useFrame` uTime update (freeze rotation) and set timelines' final state directly (opacity 1 / display flex) without animating. Add a `globals.css` fallback: `@media (prefers-reduced-motion: reduce){ *{animation:none!important;transition:none!important} }`.

### 5. Icon-only social links and email button have no accessible name
- **Owner:** perf-a11y-auditor
- **Files:** `src/app/_components/homepage/nav-list.tsx:70-87` (GitHub), `88-114` (LinkedIn), `116-135` (email button)
- **Why:** GitHub/LinkedIn anchors and the email `<button>` contain only inline SVGs — no text, aria-label, or `<title>`. Screen readers announce bare "link"/"button" (WCAG 2.4.4 / 4.1.2).
- **Fix:** Add `aria-label` ("GitHub profile", "LinkedIn profile", "Email Ron"); mark each SVG `aria-hidden="true" focusable="false"`. Replace the JS `window.location.href` email button with a real `<a href="mailto:...">` so it works without JS and is keyboard/right-click friendly.

### 6. `cursor-none` globally with no visible keyboard focus state
- **Owner:** perf-a11y-auditor
- **Files:** `src/app/layout.tsx:24` (`cursor-none` on body), `src/styles/globals.css` (no focus styles); interactive elements in `nav-list.tsx` / `experience-section.tsx` use only `hover:`
- **Why:** Tailwind Preflight resets the native focus outline, no `:focus-visible` rule exists anywhere, and the body hides the cursor. Keyboard users get neither a cursor nor a focus indicator (WCAG 2.4.7).
- **Fix:** Add `*:focus-visible{ outline:2px solid #5786F5; outline-offset:2px }` to globals.css and add `focus-visible:` variants to links/buttons/job cards. Scope `cursor-none` to `@media (pointer: fine)` so touch/keyboard contexts keep the native cursor.

### 7. Multiple nested/duplicate `<main>` landmarks
- **Owner:** ui-component-builder (also raised by perf-a11y-auditor)
- **Files:** `src/app/page.tsx:8`, `src/app/_components/main-screen.tsx:17`, `src/app/_components/experience-section.tsx:101`, `src/app/_components/homepage/particle-display/particle-display.tsx:24`
- **Why:** Four+ `<main>` elements (and five at runtime, since ParticleDisplay mounts twice — see item 8). A document must have exactly one `<main>`; nesting/duplication confuses screen-reader landmark navigation (WCAG 1.3.1).
- **Fix:** Keep one `<main>` in `page.tsx`. Change `main-screen.tsx:17` to `<section>`/`<div>`, `experience-section.tsx:101` to `<section aria-label="Experience">`, and `particle-display.tsx:24` to a `<div>` (decorative).

### 8. ParticleDisplay mounts twice — two live WebGL contexts and RAF loops always running
- **Owner:** shader-particle-specialist (overlaps perf-a11y-auditor mobile-perf finding)
- **Files:** `src/app/_components/homepage/nav-list.tsx:28` and `:49`
- **Why:** `<ParticleDisplay />` is rendered in both a `lg:hidden` and a `hidden lg:flex` wrapper. Tailwind only toggles CSS `display` — both React subtrees mount on every viewport, so two `<Canvas>` instances each spin up a WebGL context, a 120KB/10k-particle buffer, and a continuously-running `useFrame` loop, one of them for an invisible canvas.
- **Fix:** Render ParticleDisplay once via a shared wrapper, or conditionally mount with a `useMediaQuery` hook so only the visible instance exists. Use `frameloop="demand"` and/or an IntersectionObserver to pause the loop when off-screen.

### 9. Particle field is heavy for mobile: 10k additive particles + always-on loop + OrbitControls
- **Owner:** perf-a11y-auditor
- **Files:** `src/app/_components/homepage/particle-display/particle-display.tsx:34` (`count={10000}`), `:29` (OrbitControls), `:157-163` (AdditiveBlending), `:24` (fixed 300×300 wrapper, also raised separately)
- **Why:** 10k additively-blended points rotate every frame even when scrolled off-screen — a battery/GPU/TTI cost on mobile. OrbitControls is the only drei import yet lets users rotate a purely decorative element; the wrapper is hard-coded `h-[300px] w-[300px]` with no responsive handling.
- **Fix:** Pause `useFrame` off-screen (`frameloop="demand"` + IntersectionObserver), reduce count to ~2500–4000 on coarse-pointer devices via matchMedia, drop OrbitControls to trim the drei dependency, mark the Canvas container `aria-hidden="true"`, and use responsive sizing (`w-full max-w-[300px] aspect-square`). Pairs naturally with item 8.

### 10. Broken heading hierarchy — first heading is `<h2>`, the only `<h1>` is hidden, name isn't a heading
- **Owner:** perf-a11y-auditor
- **Files:** `src/app/_components/homepage/nav-list.tsx:32-38`, `src/app/_components/experience-section.tsx:102`
- **Why:** "Ron Rounsifer" is an `<a>`, not a heading; the only `<h1>` ("experience") is `lg:hidden` and renders after the `<h2>`, so heading navigation starts at h2 with no h1 (WCAG 1.3.1).

### 22. Incorrect spherical-distribution math for particles
- **Owner:** shader-particle-specialist
- **Files:** `src/app/_components/homepage/particle-display/particle-display.tsx:116`
- **Why:** `MathUtils.randFloatSpread(360)` feeds ~±180 into `sin/cos` (which take radians), and the same symmetric spread is reused for polar and azimuth, so the cloud is non-uniform/clumped. The current look is incidental and fragile to edits. No crash.
